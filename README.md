# Релиз под давлением

Короткая браузерная игра для дня открытых дверей по специальности **09.02.11 «Разработка и управление программным обеспечением»**. Игрок ведёт команду веб-сервиса записи на мероприятия через шесть этапов и видит, как решения меняют сроки, качество, людей и доверие заказчика.

Прохождение занимает около 5–8 минут. Регистрация и сервер не нужны.

## Запуск

Нужны Node.js 20+ и npm.

```bash
npm install
npm test
npm run dev
```

Игра откроется на `http://127.0.0.1:5173/`.

Сборка статики:

```bash
npm run build
npm run preview
```

Готовые файлы лежат в `dist/`.

## Публикация на GitHub Pages

1. Создайте репозиторий и отправьте в него код.
2. В настройках репозитория откройте **Pages**.
3. В качестве источника выберите **GitHub Actions**.
4. Workflow уже лежит в `.github/workflows/pages.yml`: он запускает тесты, собирает проект и публикует папку `dist`.
5. Либо вручную выложите содержимое `dist` в ветку `gh-pages`. Файл `.nojekyll` уже попадает в сборку из `public/`.

Отдельный `base` в `vite.config.js` менять не нужно: стоит `base: './'`.

## Как устроена игра

1. Стартовый экран и кнопка «Начать проект».
2. Знакомство с сервисом, командой и четырьмя показателями.
3. Шесть этапов подряд. На каждом — три варианта.
4. До кнопки «Принять решение» выбор можно менять. После неё ход фиксируется.
5. Показываются последствие, реакция ролей, сдвиг показателей и вывод этапа.
6. Итог и кнопка «Пройти ещё раз».

Порядок трёх вариантов перемешивается в начале прохождения и не меняется при обновлении страницы. До выбора ни один вариант не помечен как верный.

Если выбран быстрый рискованный или частичный ход, экран коротко вспыхивает и трясётся: это сигнал, что решение ошибочное. Затем игра спокойно объясняет последствия и идёт дальше. Ошибочный ход не заканчивает партию. При `prefers-reduced-motion: reduce` тряска и вспышка отключаются, текст предупреждения остаётся.

Звук можно выключить кнопкой «Звук» в шапке.

## Правила показателей

Четыре числа от 0 до 100, старт у каждого — **70**:

| Ключ | На экране | Смысл |
|---|---|---|
| `time` | Запас времени | Можно ли успеть к обещанному сроку |
| `quality` | Качество | Надёжность и возможность менять систему |
| `team` | Команда | Нагрузка, мотивация, общая работа |
| `trust` | Доверие | Понимает ли заказчик, что получит |

У каждого варианта в `src/data/scenario.js` заданы целые изменения всех четырёх чисел. После выбора новое значение считается так:

```text
новое = ограничить(текущее + изменение, от 0 до 100)
```

На экране показывается уже применённая разница. Если число упёрлось в 0 или 100, игрок видит фактический сдвиг, а не исходный коэффициент.

Итог по финальным числам, в таком порядке:

1. Все четыре **не ниже 50** — «Устойчивый релиз».
2. Хотя бы одно **ниже 25** — «Проект в кризисе».
3. Иначе — «Релиз с последствиями».

Текст итога дополнительно смотрит на самый низкий показатель. При равенстве называются все такие показатели.

Хороший ход может тратить запас времени. В данных системный путь заканчивается около 51 по времени и выше 90 по остальным — это устойчивый релиз, но не «бесплатная» аккуратность. Путь из одних частичных решений остаётся в диапазоне 25–49 хотя бы по одному показателю. Путь из одних рискованных решений опускает качество ниже 25.

Проверка этих трёх путей: `npm test`.

## Как править сценарий

Весь текст этапов, варианты, коэффициенты, реакции ролей и учебные выводы лежат в `src/data/scenario.js`. Логика экрана их не дублирует.

У варианта поля:

- `tier`: `risk`, `partial` или `system`;
- `effects`: четыре целых числа;
- `scare`: короткая фраза для тревожной анимации, только у `risk` и `partial`;
- тексты последствия, реакций и пояснений к каждому показателю.

После правки коэффициентов запустите `npm test`: тесты проверяют границы 0–100 и три итоговых статуса.

Если меняется смысл сохранённой партии, увеличьте `SCENARIO_VERSION`. Старые сохранения тогда не подхватятся.

Ключ прогресса в браузере: `rup-save-v1`. Настройка звука: `rup-muted`. Если хранилище недоступно, игра идёт без записи и сообщает об этом.

## Управление и доступность

- С клавиатуры: Tab, стрелки по вариантам, Enter на кнопке «Принять решение».
- Фокус виден обводкой.
- Изменения показателей подписаны словами «выросло», «упало» или «без изменений», не только цветом.
- Интерфейс рассчитан на ширину от 360 пикселей.
- Весь текст для игрока на русском, без профессиональных сокращений. Идеи вроде зависимости от одного человека, выкладки и возврата к прошлой версии объяснены обычными словами.
